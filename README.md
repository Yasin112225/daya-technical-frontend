# کپی فرانت‌اند دایا تکنیکال

نسخه‌ی مستقل و استاتیک فرانت‌اند سایت **دایا تکنیکال** (فارسی / انگلیسی / عربی).
تمام صفحات عمومی سایت در این پوشه به‌صورت HTML آماده ذخیره شده‌اند و **بدون بک‌اند،
بدون دیتابیس و بدون پنل مدیریت** قابل مشاهده‌اند.

این پوشه فقط نمایش رابط کاربری است؛ هیچ فرمی داده‌ای ارسال یا ذخیره نمی‌کند.

این پوشه برای انتشار روی **GitHub Pages** آماده شده است: کافی است یک مخزن بسازید و
همین فایل‌ها را push کنید؛ سایت روی یک لینک HTTPS منتشر می‌شود و برای اجرا به
Django، Python، Node.js یا سرور محلی نیازی نیست.

---

## مشاهده سریع سایت

| روش | آدرس | نیازمندی |
| --- | --- | --- |
| انتشار روی اینترنت | `https://USERNAME.github.io/REPO/` | یک مخزن GitHub (بخش «انتشار روی GitHub Pages») |
| اجرای محلی | `http://localhost:8000/` | Python 3.8+ (`python serve.py`) |

## پیش‌نیاز اجرای محلی

برای اجرا فقط یکی از این دو کافی است:

- **پایتون ۳.۸ یا بالاتر** (روش پیشنهادی؛ پایتون معمولاً روی ویندوز/مک/لینوکس نصب است)
- یا **Node.js ۱۸ یا بالاتر** (اگر می‌خواهید با `npx serve` اجرا کنید)

هیچ بسته‌ای برای نصب لازم نیست؛ CSS، JS، فونت و تصاویر همه داخل پوشه هستند.

## اجرای محلی

ترمینال را باز کنید و داخل همین پوشه بروید:

```bash
cd "مسیر/کپی فرانت اند دایا تکنیکال"
python serve.py
```

سپس در مرورگر باز کنید:

```
http://localhost:8000/
```

این آدرس خودکار به نسخه فارسی (`/fa/`) هدایت می‌شود.

### روش‌های جایگزین

```bash
# ۱) سرور استاندارد پایتون
python -m http.server 8000

# ۲) با Node
npx serve .
```

برای تغییر پورت در روش اول:

```bash
python serve.py 8080
```

> مسیر فایل‌های CSS، JS، تصویر و فونت **نسبی** نوشته شده است (مثلاً
> `../../static/css/site.css`)، بنابراین صفحات هم روی سرور محلی، هم در زیرمسیر مخزن
> GitHub Pages و هم با باز کردن مستقیم فایل در مرورگر بارگذاری می‌شوند. با این حال
> برای شبیه‌سازی دقیق رفتار آدرس‌های دایرکتوری (`/fa/services/`) از `serve.py`
> استفاده کنید. سرور را همیشه از **داخل همین پوشه** اجرا کنید، نه از پوشه‌ی والد.

## انتشار روی GitHub Pages

سایت با یک Workflow آماده منتشر می‌شود: `.github/workflows/pages.yml`.
این Workflow هیچ چیزی build نمی‌کند — Python، Django و Node.js را نصب یا اجرا
نمی‌کند — فقط فایل‌های عمومی سایت را به GitHub Pages تحویل می‌دهد.

**فایل‌هایی که منتشر می‌شوند:** `index.html`، `404.html`، `.nojekyll`، پوشه‌های
`fa/`، `en/`، `ar/` و `static/`.

**فایل‌هایی که منتشر نمی‌شوند:** `README.md`، `serve.py`، `set-site-url.py`،
`.gitignore` و خود Workflow.

### مرحله ۱ — ساخت مخزن و push

اگر Git نصب است، داخل همین پوشه اجرا کنید (`USERNAME` و `REPO` را جایگزین کنید):

```bash
git init -b main
git add .
git commit -m "Publish static Daya Technical frontend"
git remote add origin https://github.com/USERNAME/REPO.git
git push -u origin main
```

یا بدون Git: در GitHub یک مخزن خالی بسازید و همه فایل‌ها و پوشه‌ها را با گزینه‌ی
«uploading an existing file» آپلود کنید. **نکته:** پوشه‌های `.github`، `fa`، `en`،
`ar` و `static` و فایل `.nojekyll` هم باید آپلود شوند؛ اگر drag & drop مرورگر
فایل‌های مخفی را نبرد، همان روش Git مطمئن‌تر است.

### مرحله ۲ — فعال‌سازی GitHub Pages

1. در مخزن به **Settings → Pages** بروید.
2. در **Build and deployment → Source** گزینه‌ی **GitHub Actions** را انتخاب کنید
   (نه «Deploy from a branch»).
3. در تب **Actions** اگر پیامی درباره‌ی غیرفعال بودن Workflow دیدید،
   **I understand my workflows, go ahead and enable them** را بزنید.
4. اگر Workflow خودکار اجرا نشد، در تب **Actions** روی
   *Deploy static site to GitHub Pages* → **Run workflow** بزنید.

پس از پایان اجرا (حدود ۳۰ تا ۹۰ ثانیه) آدرس سایت این است:

```
https://USERNAME.github.io/REPO/
```

صفحه‌ی اصلی به‌طور خودکار به `/fa/` می‌رود و از همان‌جا منوی تغییر زبان
(فا / EN / ع) کار می‌کند.

### مرحله ۳ (اختیاری، فقط یک‌بار) — به‌روزرسانی آدرس متادیتا

برای موتورهای جست‌وجو و پیش‌نمایش شبکه‌های اجتماعی، هر صفحه یک آدرس **مطلق**
دارد (`canonical`، `hreflang`، `og:url`، `og:image` و بلوک JSON-LD). این آدرس‌ها را
نمی‌توان نسبی نوشت، بنابراین در این نسخه با مقدار جای‌گزین
`https://YOUR-USERNAME.github.io/YOUR-REPO/` ذخیره شده‌اند. پس از ساخته‌شدن مخزن،
یک‌بار این را اجرا کنید:

```bash
python set-site-url.py https://USERNAME.github.io/REPO
```

اسکریپت هر ۷۹ صفحه را می‌نویسد و تعداد تغییرها را گزارش می‌کند. اجرای دوباره‌ی آن با
آدرس جدید (مثلاً پس از تغییر نام مخزن) بی‌خطر است. **نمایش سایت به این مقدار وابسته
نیست**؛ همه‌ی لینک‌ها، CSS، JS، فونت و تصاویر نسبی‌اند و بدون این مرحله هم سایت کامل
کار می‌کند — فقط آدرس‌های SEO به مخزن واقعی اشاره نمی‌کنند.

> اگر سایت را روی مخزن ویژه‌ی کاربر (`USERNAME.github.io`) منتشر می‌کنید، آدرس را
> بدون نام مخزن بدهید: `python set-site-url.py https://USERNAME.github.io`

### به‌روزرسانی‌های بعدی

هر `git push` روی شاخه‌ی `main` (یا `master`) باعث انتشار مجدد می‌شود. برای انتشار
دستی از تب Actions گزینه‌ی **Run workflow** را بزنید.

## آدرس صفحات

آدرس‌ها در حالت محلی همان‌طور که در جدول آمده است؛ روی GitHub Pages یک پیشوند
`/REPO/` به همه اضافه می‌شود (مثلاً `/REPO/fa/services/`).

| صفحه | فارسی | English | العربية |
| --- | --- | --- | --- |
| صفحه اصلی | `/fa/` | `/en/` | `/ar/` |
| خدمات | `/fa/services/` | `/en/services/` | `/ar/services/` |
| جزئیات خدمت | `/fa/services/<slug>/` | … | … |
| صنایع | `/fa/industries/` | `/en/industries/` | `/ar/industries/` |
| جزئیات صنعت | `/fa/industries/<slug>/` | … | … |
| فرایند همکاری | `/fa/process/` | `/en/process/` | `/ar/process/` |
| تأمین مالی نوین | `/fa/financing/` | `/en/financing/` | `/ar/financing/` |
| پرسش‌های متداول | `/fa/faq/` | `/en/faq/` | `/ar/faq/` |
| درباره ما | `/fa/about/` | `/en/about/` | `/ar/about/` |
| تماس با ما | `/fa/contact/` | `/en/contact/` | `/ar/contact/` |
| درخواست بررسی پروژه | `/fa/project-request/` | … | … |
| صفحه تأیید (نمایشی) | `/fa/project-request/received/` | … | … |
| حریم خصوصی | `/fa/legal/privacy/` | … | … |
| شرایط استفاده | `/fa/legal/terms/` | … | … |
| محدودیت خدمات | `/fa/legal/disclaimer/` | … | … |

در مجموع **۷۸ صفحه** (۲۶ مسیر × ۳ زبان) به‌همراه صفحه ۴۰۴ (`404.html`) و صفحه هدایت
ریشه (`index.html`). آدرس‌ها همان آدرس‌های پروژه اصلی هستند و تغییر زبان از هدر یا
منوی موبایل کار می‌کند: از `/fa/services/mining/` به `/en/services/mining/`.

بارگذاری مستقیم صفحات عمیق کار می‌کند؛ هر مسیر در پوشه‌ی خودش یک `index.html` دارد،
بنابراین `https://USERNAME.github.io/REPO/fa/services/mining/` را می‌توان مستقیم
باز کرد یا به اشتراک گذاشت.

## ساختار پوشه

```
کپی فرانت اند دایا تکنیکال/
├── index.html              ← هدایت ریشه به /fa/
├── 404.html                ← صفحه خطای فارسی (برای هاست‌های استاتیک)
├── serve.py                ← سرور محلی (پورت ۸۰۰۰)
├── set-site-url.py         ← به‌روزرسانی آدرس‌های SEO پس از انتشار
├── .nojekyll               ← جلوگیری از پردازش Jekyll روی هاست‌های استاتیک
├── .gitignore              ← فایل‌های محلی/حساس وارد مخزن نمی‌شوند
├── .github/workflows/pages.yml  ← انتشار خودکار روی GitHub Pages
├── fa/ en/ ar/             ← صفحات هر زبان، هر مسیر در پوشه خودش با index.html
└── static/
    ├── css/site.css        ← استایل اصلی پروژه (بدون تغییر)
    ├── css/demo.css        ← استایل نوار و پیام حالت نمایشی (جدید)
    ├── js/site.js          ← تعاملات اصلی پروژه (بدون تغییر)
    ├── js/demo.js          ← مدیریت نوار نمایشی و فرم‌ها (جدید)
    ├── fonts/              ← Vazirmatn و Inter به‌صورت محلی + fonts.css
    ├── images/             ← تصویر Hero (dayate.png / dayate.webp)
    └── img/                ← لوگو، فاوآیکون و تصویر OG
```

## مسیرها و زیرمسیر مخزن

- تمام لینک‌های داخلی، تصاویر، فونت‌ها، CSS و JS **نسبی** هستند؛ هیچ آدرسی با
  `/static/...` یا `/fa/` (مطلق از ریشه‌ی دامنه) نوشته نشده است. به همین دلیل سایت
  در زیرمسیر `/REPO/` درست کار می‌کند و نام مخزن روی کارکرد آن اثری ندارد.
- صفحه ۴۰۴ چون برای هر مسیر ناموجود در هر عمقی نمایش داده می‌شود، ریشه‌ی سایت را
  هنگام بارگذاری تشخیص می‌دهد: اگر نشر از نوع پروژه (`USERNAME.github.io/REPO/`)
  باشد از `/REPO/` و اگر مخزن ویژه‌ی کاربر (`USERNAME.github.io/`) باشد از `/` استفاده
  می‌کند. این بررسی با یک تلاش دوباره‌ی محافظت‌شده انجام می‌شود و حلقه ایجاد نمی‌کند.
- GitHub Pages درخواست `/REPO/fa/services` را به `/REPO/fa/services/` هدایت می‌کند و
  سپس `index.html` همان پوشه را می‌فرستد.

## حالت نمایشی (Demo)

از آنجا که بک‌اندی وجود ندارد:

1. **نوار بالای صفحه** در همه صفحات می‌گوید نسخه نمایشی است و داده‌ای ارسال/ذخیره
   نمی‌شود. با دکمه × برای همان نشست بسته می‌شود.
2. **فرم تماس** و **فرم درخواست بررسی پروژه** اعتبارسنجی سمت مرورگر را انجام می‌دهند،
   اما درخواستی به سرور نمی‌فرستند. پس از تکمیل فیلدهای الزامی، پیامی با عنوان
   «نسخه نمایشی» نمایش داده می‌شود؛ هیچ پیام موفقیّت واقعی جعل نشده است.
3. **صفحه تأیید درخواست** (`project-request/received/`) قابل مشاهده است، ولی شناسه
   آن نمونه (`DEMO-1405-0001`) است و یادداشتی بالای صفحه توضیح می‌دهد که در این نسخه
   هیچ درخواستی ثبت نشده است.
4. **ورود / حساب کاربری** وجود ندارد؛ صفحات عمومی هیچ‌کدام به نشست کاربر وابسته نیستند.
5. **داده‌ها ثابت هستند**: محتوای خدمات، صنایع و پرسش‌ها همان محتوایی است که هنگام
   استخراج از دیتابیس پروژه اصلی خوانده شده و در HTML ذخیره شده است.

## تفاوت با پروژه اصلی

**حذف شده (چون بک‌اند است):** کد Django (`apps/`, `config/`, `manage.py`)، دیتابیس
`db.sqlite3`، فایل `.env` و کلیدها، پنل مدیریت و CRM، ماژول‌های جمع‌آوری پیام،
ایمیل اطلاع‌رسانی، sitemap پویا و robots، media بلاگ/CRM، و `venv`.

**اضافه شده:** `index.html` (هدایت ریشه)، `404.html`، `serve.py`، `set-site-url.py`،
`.nojekyll`، `.github/workflows/pages.yml`، `static/css/demo.css`، `static/js/demo.js`
و پوشه `static/fonts/`.

**تغییر یافته در خروجی HTML:** حذف ورودی CSRF فرم‌ها، افزودن `data-demo-form` به دو
فرم، جایگزینی لینک Google Fonts با فونت محلی، افزودن نوار نمایشی و اسکریپت/استایل
نمایشی به هر صفحه، تبدیل همه‌ی آدرس‌های داخلی و منابع به مسیرهای نسبی و تنظیم
آدرس‌های SEO روی دامنه‌ی GitHub Pages. ظاهر، چیدمان، رنگ‌ها و متن‌ها دست‌نخورده مانده‌اند.

## فونت‌ها

فونت‌های `Vazirmatn` (فارسی/عربی) و `Inter` (انگلیسی) از Google Fonts دانلود و به‌صورت
محلی در `static/fonts/` نگه داشته شده‌اند؛ بنابراین نمایش صفحات به اینترنت وابسته
نیست. هر دو فونت تحت مجوز SIL Open Font License هستند.

## محدودیت‌ها

- فرم‌ها داده‌ای ذخیره نمی‌کنند و ایمیلی ارسال نمی‌شود (بک‌اندی وجود ندارد). ارسال
  فرم با POST روی هاست استاتیک معنایی ندارد و پاسخ واقعی دریافت نمی‌کند.
- فیلتر/جست‌وجوی سمت سرور وجود ندارد؛ صفحات فهرست، همه محتوای فعال پروژه اصلی را
  یک‌جا نشان می‌دهند.
- تگ‌های `canonical` و `hreflang` و `og:` روی دامنه‌ی GitHub Pages تنظیم می‌شوند و تا
  پیش از اجرای `set-site-url.py` مقدار جای‌گزین
  `https://YOUR-USERNAME.github.io/YOUR-REPO/` را نشان می‌دهند. نمایش سایت به آن‌ها
  وابسته نیست.
- صفحه ۴۰۴ فقط فارسی است (هاست‌های استاتیک از `404.html` ریشه استفاده می‌کنند).
- محتوا «فریز» شده است: برای انتشار تغییرات جدید محتوا باید صفحات از پروژه اصلی
  دوباره استخراج شوند (این پوشه شامل کد Django نیست).

## بازتولید خروجی

اگر محتوای پروژه اصلی تغییر کرد، باید صفحات دوباره رندر شوند. روش کار: پروژه اصلی را
در یک کپی جداگانه با `DEBUG=False` و ذخیره‌سازی استاتیک ساده اجرا کنید، همه مسیرهای
`/fa|en|ar/…` را با Django test client رندر کنید و همان اصلاحات بالا (حذف CSRF،
فونت محلی، نوار نمایشی، نسبی‌کردن مسیرها) را دوباره اعمال کنید.
